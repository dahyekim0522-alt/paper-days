# 실행 검증 기록

검증일: 2026-11-05 (한국 시간). 환경: Linux, Node.js 24.22.1, npm 11.9.0, 시스템 Chromium. 테스트는 개발 서버 origin별 격리된 브라우저 컨텍스트를 사용하며 실제 사용자 기록을 만들지 않습니다.

| 검사 | 결과 |
| --- | --- |
| `npm ci --no-audit --no-fund` | lockfile 기반 재설치 성공 |
| `npm run build` | TypeScript 검사 및 Vite production 빌드 성공 |
| `npm test` | 1개 파일, 8개 테스트 통과 |
| `npm run test:e2e` | 12개 Chromium 테스트 통과 |

## 단위 테스트 8개

- 윤년, 잘못된 날짜, 누락·비정상 값 검증
- 연도 경계 이동과 고정 6페이지 매핑
- 같은 날짜의 저장이 기존 ID와 1개 기록을 유지함
- 사진 Blob 저장 및 제거
- 비정상 날짜 저장 거부
- 일기와 사진 바이트 복원
- 잘못된 버전·중복 날짜·누락 사진·손상된 사진 구조 거부
- 잘못된 백업은 기존 기록을 보존함

## 브라우저 테스트 12개

1. 빈 표지 열기, 한국어 여러 문단 입력, 감정, 사진 변환/첨부, 자동 저장, 새로고침 유지, 수정, 중복 방지, 안전한 텍스트 렌더링, 검색, JSON 다운로드, 삭제, 사진 포함 복원, 달력 이동
2–6. 각각 360 / 390 / 768 / 1280 / 1920px에서 앞뒤 페이지 이동과 가로 넘침 검사
7. 키보드·모션 감소·빠른 반복 넘김 시 페이지 수 제한과 편집 중 페이지 보호
8. CDP 실제 터치 이벤트로 모바일 정방향/역방향 스와이프와 가로 회전 후 가로 넘침 검사
9. IndexedDB put에 QuotaExceededError를 주입하여 저장 실패 안내·입력 보존·정상화 후 재시도
10. PC 모서리에서 마우스 드래그하여 페이지 이동
11. 자동 저장 이전 새로고침에서 초안 복구, 손상 이미지 오류, 날짜 변경 후 기존 기록 다시 열기
12. 이미 자동 저장된 수정도 취소 시 편집 전 기록으로 복원

초기 검증에서 발견한 portrait 역방향 버튼 및 터치 방향 오류를 보완한 후 전체 테스트를 다시 실행했습니다. 사진 테스트 입력의 손상된 PNG를 정상 PNG로 교체했으며, 별도의 손상 이미지 거부 검사를 추가했습니다.

## 미검증

실제 iOS/Android 기기, Safari/Firefox, Windows 직접 실행, 수만 건 기록 부하, GitHub Pages 원격 배포는 수행하지 않았습니다. 클라우드 환경의 draft 저장은 환경 게시나 새 작업에서의 복원 검증을 뜻하지 않습니다.
